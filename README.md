# BloodNet — سرویس هماهنگی زنجیره تأمین خون استان ساختگی

سرویس BloodNet بین بیمارستان‌ها (تقاضا)، مراکز انتقال خون (موجودی) و اهداکنندگان (عرضه) در یک استان ساختگی ارتباط برقرار می‌کند: درخواست بیمارستان ثبت می‌شود، موجودی سازگار و غیرمنقضی با ترتیب FEFO تخصیص می‌یابد، کسری از طریق دعوت هدفمند اهداکنندگان واجد شرایط (از طریق Gateway شبیه‌سازی‌شده) تأمین می‌شود و پاسخ‌ها به‌صورت idempotent پردازش می‌شوند تا در هر لحظه تصویر صادقانه‌ای از تأمین/کسری وجود داشته باشد.

> تمام داده‌ها ساختگی هستند و صرفاً برای مسابقه برنامه‌نویسی تولید شده‌اند. این سرویس هیچ ادعای پزشکی ندارد و نباید برای هیچ تصمیم درمانی واقعی استفاده شود.

مرجع قطعی نام‌ها و قراردادها: [docs/CONTRACT.md](docs/CONTRACT.md)

## پیش‌نیاز

- Python 3.10 یا جدیدتر
- بدون هیچ وابستگی خارجی دیگر — همه چیز به‌صورت محلی اجرا می‌شود.

## اجرای یک‌دستوری از محیط تمیز

ویندوز (PowerShell):

```powershell
scripts\setup.ps1
scripts\run.ps1
```

لینوکس/macOS (bash):

```bash
scripts/setup.sh
scripts/run.sh
```

پس از اجرا، سرویس روی `http://localhost:8000` بالا می‌آید و `GET /health` پاسخ `{"ok": true}` می‌دهد.
سرویس‌های کیت (Gateway :9100، Travel :9200، Inventory :9300) توسط هارنس تمرینی راه‌اندازی می‌شوند.

تنظیمات از فایل `.env` خوانده می‌شوند (الگو: `.env.example` — شامل توکن‌های دموی ثابت کیت). در نبود `.env`، مقادیر پیش‌فرض همان مقادیر کیت هستند.

## رابط‌های کاربری

| آدرس | نما | توکن |
|---|---|---|
| `http://localhost:8000/` | کارمند بیمارستان (ثبت و پیگیری درخواست) | `hospital-token` |
| `http://localhost:8000/center.html` | کارمند مرکز (موجودی و تخصیص) | `coordinator-token` |
| `http://localhost:8000/donor.html` | جریان تعامل اهداکننده (دمو) | — |

## تست‌ها

```bash
.venv\Scripts\python -m pytest tests/ -q      # ویندوز
.venv/bin/python -m pytest tests/ -q          # لینوکس/macOS
```

## Smoke (قرارداد + سناریوی تمرینی)

ابتدا سرویس را بالا بیاورید، سپس:

```bash
.venv\Scripts\python scripts\smoke.py --team http://127.0.0.1:8000 --scenario P-normal --seed 1000
```

این اسکریپت قرارداد رسمی (harness contract tests) و سناریوی P-normal را اجرا و خلاصه امتیاز تمرینی را از `run_out/result.json` چاپ می‌کند.

## مسیر دمو

1. `scripts\setup.ps1` و `scripts\run.ps1`
2. باز کردن `http://localhost:8000` (نمای بیمارستان)
3. ثبت درخواست برای بیمارستان ثبت‌شده (مثلاً H07) → مشاهده تخصیص موجودی و موج دعوت
4. در صورت pending_review → تأیید توسط هماهنگ‌کننده در `center.html`
5. شبیه‌سازی پاسخ اهداکننده در `donor.html` → مشاهده به‌روزرسانی صادقانه شمارنده‌ها تا `fulfilled`
